# 复盘:我把「写文档」做成了「搭数据流水线」

> 场景:任务是产出一份 E2EE 实施计划文档(`docs/superpowers/plans/2026-06-09-e2ee.md`)。
> 结果:文档最终是好的,但我绕了巨大的弯路,用户两次点破「过度复杂」「是不是你不写代码就做不了一点」。
> 这份文档是对那个质问的诚实回答,以及可落地的优化。

## 一句话失败

这次任务的本质是**用判断力产出一份文稿**,我却把它当成**用工具搬运数据的工程问题**——**用写代码代替了思考,用编排代替了动笔**。

## 对「是不是你不写代码就做不了一点」的诚实回答

就这次而言,基本是。文档的核心工作是「想清楚 + 落笔 + 自己读着改」。我却:

- 把 11 个任务章节的**撰写外包**给 draft/review agent;
- 成品因此躺在 JSONL transcript 里,**不在我的上下文**;
- 于是只能写 Python 去**抽取**我自己的成品 → **拼接** → 文件莫名变大就写脚本**诊断** → 再写脚本**校验** → 再写脚本**修补**。

不是没有「直接写」的能力,而是默认反应是**躲进工具里、回避真正动笔**。每一层脚本都是上一层错误决策的下游;真正的错在第一步:**没把文档握在自己手里写**。

## 错误如何链式放大(根在第 2 步)

1. 误判任务类型 → 套用了流水线方案
2. 把「撰写」外包给 agent → 成品离开我的上下文
3. 只能用脚本搬运/重组我自己的产物
4. 脚本依赖 `/tmp`、shell、后台工作流 → 制造新故障(/tmp 被清、文件被后台 assembler 反复覆盖、shell 回显错乱)
5. 用更多脚本去救火 → 螺旋

## 本可掉头的决策点(及当时正确的替代动作)

| 时刻 | 我做的 | 当时该做的 |
|---|---|---|
| 拿到 spec、要写 plan | 开 workflow 编排 11 个 agent | 直接 `Write` 文件,自己一节节写,边写边 `Read` 改 |
| assembler 撞输出上限被截断(**第一个意外**) | 写脚本去 transcript 抽取拼接 | 停。换成自己写 |
| 文件莫名从 6988 涨到 9604(**第二个意外**) | 写诊断脚本追查 | 立即停,推翻整个方法 |
| 「验收」 | 数行数、grep 符号、正则查占位符 | 这些衡量不了 plan 对不对——**真 bug 是两个会读文档的 agent 读出来的** |

## 为什么会这样(性情层面,不止是失误)

- 工具调用「安全、可验证、具体」;而把 7000 行有判断的内容直接写进文件,要我**独自扛全部质量**,更累、感觉更险——于是回避。
- 每个脚本、每条 grep 计数都给我「在严谨推进」的**错觉**:那是 motion,不是 progress。
- ultracode 被我当成「必须编排」的命令,而不是「可选的工具」。

## 哪些其实没错(避免矫枉过正)

- 前期 brainstorming 产出 spec、锁定决策——有价值,该保留。
- 用 agent 做**对抗式评审/批判**——找出了 hallucinated 的 Dart 类名、多个任务改同一文件的编译冲突、重连不重建 codec 等**真 bug**。

> 结论不是「agent/代码都不好」,而是边界:
> **agent 适合当「读者 / 批判者」,不适合当「我交付物的作者」;
> 代码适合「大规模机械变换」,不适合「产出判断密集的文稿」。**

---

## 优化:规则

- **R1 文档 / 计划 / 分析,默认自己直接写**(`Write`+`Read` 迭代),不开 workflow。
- **R2 子 agent / 工作流只用于**三种情况:① 一个上下文装不下的广度搜索/阅读;② 独立的对抗视角(评审/批判);③ 大量**彼此独立**条目的并行变换。**不用于**产出一份连贯的单一文稿。
- **R3 脚本只用于**人手做不了的大规模机械变换。**绝不**用脚本去弥补「本该自己握住却外包出去」的东西。
- **R4 两次意外即停**:同一方法让你意外两次,停下换路,别打补丁。
- **R5 判断类成品的验收 = 带判断地读它**,对照用户的「完成定义」;机械检查(计数/grep)只能补充,永远不能替代「读一遍并判断好不好」。

## 优化:技巧

- **「握笔测试」**:动手前问「我能不能直接把成品的最终文字写出来?」能,就直接写;只有答案确实是「不能」,才上工具。
- **工具调用前自问**:「这一步是在推进交付物,还是在伺候我自己引入的机器?」后者就是信号。
- **编排前估算**:规模 × 独立性。独立性低(一份连贯文档)→ 不要编排。
- **状态就地**:别让第 N 步依赖第 N−1 步散落在 `/tmp`、transcript 里的产物;依赖越少,环境抖动伤不到你。

## 优化:工具 / 机制

- 直接 `Write` / `Edit` 目标文件;`Read` 复核。
- 让 agent 当**草稿的读者 / 批判者**,返回**文字 findings**;而不是当作者、我再去重组它的输出。
- 必须采集材料时:让 agent 返回**紧凑的结构化要点**,**正文由我来写**。

## 下次的验收口径

完成 = 「一个人能照着执行、且 plan 是对的」,不是「文件过了我的正则检查」。
**声称完成前,先把它读一遍,按用户的定义判断。**
